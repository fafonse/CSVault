## Interviewer Practices

### Good Practices
1. The interviewer immediately and positively let the user know when they were deleting their emails (potentially "harming" themselves)
	- This speeds up the entire process while also keeping the user "safe" from their own mistakes
	- This practice was beneficial in preventing the user from causing harm to themselves within the test, which allows the rest of the think aloud to occur without risk. 
2. The interviewer doesn't immediately give the user the correct answer to their problem. When he does give the answer, he tries to keep it to hints rather than straight up telling them.
	- It's important to allow a user to properly "explore" their problem, that's where all the insight is anyways. Keeping the real answer to hints also helps speed up the process while still allowing the *thinking* part of a think aloud to occur. 
	- This was vital to actually seeing the user's thought process and mental model, as you need the user to explore by themselves a bit to really see how they think.

### Bad Practices
1. The interviewer tells the user that their method of opening the start menu is "irregular" and is not what people normally do
	- The start menu can be interacted solely with the mouse, and therefore that's a completely valid and normal way for someone to use the system. Interviewers should not shame or be rude to their users, since we want their honest first-impressions and thoughts. 
2.  The interviewer provides superfluous information/hints
	- While interacting with the File Explorer, the interviewer gives information that is confusing and hard to understand, especially for a non-expert user. This caused the user more frustration and confusion, which isn't good for a study.
3. The interviewer gives vague instructions to the user
	- Originally the user is told "Save a text file", then to "Save a document", then "Save a text file using Notepad". This is confusing to the user and increases the amount of time it takes for them to respond. This could have been avoided by having detailed and specific tasks planned beforehand. 
4. Instead of engaging with confusion, he just repeats himself
	- When the user is confused about the task at hand, the interviewer simply repeats the task objective again. The interview could have instead engaged with the user's thought process and asked them questions such as "Where would you guess the (thing) is at?" or "Are you looking for a key or a on-screen button to press?". This would have yielded more useful information regarding the overall *user journey*. 

## Usability Aspect Reports

### Positive Usability Aspects
1.  Window Pane desktop has great clarity and makes everything a normal user needs easily available
2. Allowing users to swap between desktops for personalization
### Negative Usability Aspects
1.  There is no clearly visible way of closing a window (recall vs. recognition)
2.  Internet Explorer doesn't have it's search bar in great contrast or view on startup
3.  Start menu is not clearly visible on screen (recall vs. recognition)
4. 2 desktop environments leads to more confusion and a greater learning curve
